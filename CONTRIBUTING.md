# Contributing to ShakeBoard

Thanks for helping improve ShakeBoard. Please keep changes focused and preserve its local-first privacy model.

## Prerequisites

- macOS 14 or later
- Xcode 26 or later
- Tuist 4.202.0

CI pins Tuist 4.202.0. When updating it, bump Tuist together with Xcode and replace the pinned SHA-256 with the new
value from that Tuist release's `SHASUMS256.txt`.

## Generate and build

Generate the Xcode workspace without opening Xcode:

```bash
tuist generate --no-open
```

Build with DerivedData outside the repository and without the maintainer's signing identity:

```bash
xcodebuild \
  -workspace ShakeBoard.xcworkspace \
  -scheme ShakeBoard \
  -configuration Release \
  -derivedDataPath /tmp/shakeboard-build \
  CODE_SIGNING_ALLOWED=NO \
  CODE_SIGN_IDENTITY="" \
  DEVELOPMENT_TEAM="" \
  build
```

The workspace is generated by Tuist and ignored by Git. Run `tuist generate --no-open` again after changing
`Project.swift`. Keep DerivedData outside this repository; `/tmp` avoids iCloud extended-attribute signing issues.

## Run tests

Use the `ShakeBoardTests` scheme and a scratch DerivedData directory:

```bash
xcodebuild test \
  -workspace ShakeBoard.xcworkspace \
  -scheme ShakeBoardTests \
  -destination 'platform=macOS' \
  -derivedDataPath /tmp/shakeboard-tests \
  CODE_SIGNING_ALLOWED=NO \
  CODE_SIGN_IDENTITY="" \
  DEVELOPMENT_TEAM=""
```

Unit tests must never access the real general pasteboard or the real
`~/Library/Application Support/ShakeBoard` directory. Inject pasteboard, filesystem, clock, and event dependencies and
use a temporary directory or test defaults suite.

## Run a development build safely

Always set `SHAKEBOARD_DATA_DIR` to a disposable scratch directory before launching a development build. The legacy
`PERCH_DATA_DIR` name remains supported, but `SHAKEBOARD_DATA_DIR` takes precedence when both are set. Never point a
development build at your real `~/Library/Application Support/ShakeBoard` directory: development schemas and migration
tests can make that data unreadable by an installed release.

```bash
SHAKEBOARD_DATA_DIR=/tmp/shakeboard-dev-data \
  /tmp/shakeboard-build/Build/Products/Release/ShakeBoard.app/Contents/MacOS/ShakeBoard
```

`PERCH_DEBUG_SHOW` can open seeded UI states for manual checks and screenshots. See the development-build notes in
[`CLAUDE.md`](CLAUDE.md) for the supported values and safety constraints.

## Pull requests

- Keep each pull request small and focused.
- Describe automated tests and manual verification, including the macOS version used.
- Call out behavior that could not be verified locally.
- Do not include real clipboard contents, credentials, tokens, or personal files in tests, screenshots, or reports.
- Changes to cryptography, vault code, the Share Extension handoff, the MCP bridge, or redaction require maintainer
  review under [`.github/CODEOWNERS`](.github/CODEOWNERS).

## Developer Certificate of Origin

Every commit must include a `Signed-off-by` trailer. Create it with:

```bash
git commit -s
```

The sign-off certifies that you have the right to submit the contribution under this project's license, as described
by the [Developer Certificate of Origin](https://developercertificate.org/).
